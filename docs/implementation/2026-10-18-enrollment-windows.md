## Implementation and invariants

`activity_enrollment.rs` seeks through the existing schema-14 `watch_locator_location(repo,number,id)` covering index. First and successor statements are separate, avoiding an OR around the lower bound. Each returns at most **128 native locator identities before membership, existing-target filtering or deduplication**. The successor tuple includes stable ID, so aliases sharing a locator can span many windows without being skipped or repeatedly restarting the same window. Candidate buffers contain no payload bodies.

Each candidate performs indexed existence checks against the watch-source primary key and the exact Activity target key. Source eligibility rejects only the unique exact value `selected`, so at most two source reasons need inspection even when an identity has many reasons. Case-sensitive native repository/source semantics and signed numeric ordering remain the previous SQL semantics. Inserting one target makes later aliases at that repository/number ineligible within the same transaction; no unbounded DISTINCT set or target collection is needed. A pass stops at **128 newly inserted targets** or the end of its snapshot, preserving the previous exact repository/number enrollment prefix. Existing target deadlines/completion, including notification-derived targets, are never reset.

One SQLite transaction owns all windows, eligibility checks and inserts. A concurrent WAL writer cannot change a later window's snapshot; if it commits a target after enrollment starts reading, SQLite rejects the stale read-to-write upgrade and rolls back the pass. A fresh retry sees and preserves that target's committed deadline/completion. A pending publication explicitly blocks enrollment before native main-table scans, including when old-snapshot reader views exist; startup/repair retain responsibility for finishing publication before scheduling resumes.

There are **no new persistent cursors, tables, indexes, triggers, accounting rows or migration steps**. Schema stays **14**. The transaction's actual `total_changes` guard includes all dependent trigger writes and rolls back an over-budget pass. Successful production enrollment still costs exactly one mutation per new target, at most **128 total direct mutations**, and does not advance presentation revision. No new bookkeeping needs reservation. Restart recomputes the first missing prefix; an incomplete traversal cannot certify recovery. The existing independently evaluated recovery-readiness windows continue to reject missing or unfinished targets.

The inclusive **524,288,000-byte** shared disposable ceiling, transactional byte accounting, retained publication images, exact LRU order and atomic publication visibility remain unchanged. Enrollment creates durable target identities rather than disposable payloads. Activity/seen/dedup/progress/baseline/recovery history, terminal attempted/unavailable intents, membership/attempt records, identity, persistent Pause, validators/server deadlines and protected cached reading retain their contracts.

The bound is **per statement and candidate buffer**, not per scheduling pass or total traversal. Each pass begins at the earliest index key; many rejected locators can require many windows, and later passes may revisit that prefix. The fixtures record more windows at higher cardinality. No constant-time enrollment, bounded cumulative time, variable-key-byte, total allocator/temp-space or native-performance claim is made.

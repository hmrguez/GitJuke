## Reading behavior

Opening a retained comment, review or comment mention in Activity selects its PR and opens one exact Conversation node. The namespaced Activity identity supplies the node ID; the worker checks the retained Activity identity, PR and 90-day eligibility before queuing. A direct GraphQL lookup accepts only IssueComment, PullRequestReview and PullRequestReviewComment, with exact ID and PR number/repository ownership. Pending reviews, missing/unsupported nodes, wrong ownership and legacy REST-only identities fail explicitly. There is no page scan, whole-history retention, inferred thread ID, identity matching by author/time/body, or fixture fallback. PR-body mentions remain unsupported destinations and unseen. Request/check records retain their existing explicit excerpt destinations.

The singleton uses the existing selected-work queue/tickets, server deadlines, before/after identity/comparison checks, cancellation, global generations, shared SQLite admission/retention and bounded serialized IPC. It bypasses the Activity excerpt, not the reader limits: inclusive **131,072 UTF-8 bytes** per body; **921,600 bytes** serialized page; **1,048,576 bytes** IPC; **2,097,152 bytes / 100 messages** shared frontend retention. Oversized/unavailable bodies retain identity and validated source links, without a clipped body or seen receipt. An exact destination labels **exact record only** and does not claim parent-source/thread completeness. No storage migration or relaxed transport, queue, cache, mutation or retained-source ceiling is introduced.

Only an explicitly opened matching destination can submit a frontend seen receipt after DOM commit. Ordinary Conversation pages/replies no longer offer a seen control. All distinct segments must render after the destination opens; repeated visits do not count twice. A changed digest/generation/job remounts traversal state; polling the same body preserves it. A complete supplied empty review can qualify. Rust still validates selected/open/unlocked ownership, generation, permitted unexpired cache, complete body and digest; it also rejects a known newer cached overview head. Clear, denial, account lock and source eviction reject obsolete receipts. Seen updates affect the exact namespaced Activity record; adjacent/later records remain unchanged. Mark loaded page seen remains the separate explicit snapshot action. External GitHub navigation never submits receipts.

Back to Activity preserves the loaded Activity page and returns focus to the originating record. Browse Conversation sources leaves the destination and exposes the existing independent cursor pages. Reading another source never inherits seen authorization. Conversation/Changes tabs can carry the exact destination into the existing inline reader, releasing the other mounted reader. The Changes file list remains bounded and user selected; no file-list scan is added.

For exact review comments with a supplied fullDatabaseId, one REST point read obtains patch coordinates. Its node ID, exact PR API URL and body digest must match the direct node before coordinates publish. Coordinate access denial applies the Conversation visibility/generation barrier. Current/original commit, side, file and range feed the existing conservative anchor resolver. Outdated, mismatched, ambiguous, missing and unsupplied lines remain labeled. Return to diff appears only with the exact selected revision/file/side and unique supplied patch range. Resolution state is not inferred for the direct reply. No source thread identity or complete surrounding thread is inferred; use the independently bounded thread reader to browse discussions.

## Remaining limits and next slice

Source pages remain independently ordered; a merged chronological timeline is not implemented. Exact destinations show a singleton rather than guessing its surrounding thread/page. Legacy REST-only IDs and PR-body mentions need a separately validated destination strategy. Source links are offered only after validation. Direct reply coordinates require an available matching REST source and supplied patch; outdated anchors never remap onto current lines.

No existing live Activity fixture exceeds 8 KiB or has a new-unseen baseline in this history.

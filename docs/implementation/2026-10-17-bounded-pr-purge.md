# Bounded full-PR resource purge checkpoint — 2026-10-17

Status: production full-PR denial barrier, bounded reclamation, discovery restart guards, reader/startup/repair integration and targeted fault qualification implemented. Development version **0.1.0**, schema **8**. No Git repository or applicable AGENTS.md exists in the workspace or ancestors. Settled decisions are unchanged.

## Audit and implementation

Three denial paths previously had different, partly unbounded cleanup: Activity hydration called `activity_purge`; missing/denied watched heads called `purge_watch`; overview denial first purged Activity, then invoked generic `purge`, including global invalidation of unrelated staging. Published PR/list bodies, API pages, excerpts, staged Activity/discovery/checks and watch completeness could therefore change in different transactions. The Activity path did not purge the complete PR cache. Full-PR denial now uses one restartable operation in `pr_purge.rs`.

The operation commits a **four-row barrier** before reclamation: increment the global result generation, insert a per-PR marker with that generation and original local retry time, upsert the unavailable PR resource state, and increment the presentation revision. Watched-head denial checks the original stable watch ID, locator and epoch before starting a new barrier. Missing/stale targets make no mutations. Retrying a pending marker, including case-variant repository spelling, retains its generation/revision/retry time. Repository matching is case-insensitive literal equality; PR numbers are exact.

Cleanup transactions have a **global maximum of 128 direct row mutations**, shared across twelve classes: affected discovery restart guards; downloaded payloads; resource health; Activity staging; legacy staging; source staging; staged/published check contexts; targeted pending descriptors; check completeness; watch epoch/error/review/retry metadata; Activity target completion; and superseded check-purge markers. Final PR-marker removal shares the allowance. Free-space admission precedes the barrier and every batch. Each transaction holds at most one PR marker identity, without an unbounded Rust victim list.

Payload matching includes the PR overview (with its embedded stack data), Activity owner context, cached list rows for matching stable/historical locators and staged identities, all associated Activity excerpts, and exact PR/issue API roots with an end, slash or query boundary. It does not treat repository underscores as wildcards or PR 1 as PR 10. Pending cleanup uses exact locators, literal check-ID prefixes and typed job fields for overview/stack/Activity continuations. Mixed head batches retain their descriptors: matching watch epochs reject obsolete results, while other watches remain due for ordinary scheduling.

A `purged_generation` watermark lets each matching watch locator increment its epoch exactly once across partial cleanup and repair. It preserves watch membership and open/closed identity state; denial never proves closure/deletion or removes a reason. Cached review state is cleared, checks become unavailable/incomplete, and the Activity target becomes unfinished. Its existing due time is preserved. Minimal Activity, unseen/dedup/progress, baseline/recovery boundary, settings/identity/Pause, terminal attempted/unavailable intents, membership/attempt history and notification validators/server deadlines survive.

The global generation prevents pre-barrier detail/Activity results from republishing. It may reject an unrelated in-flight result, but **does not clear unrelated caches, epochs, staging or durable work**. Unlike the previous overview path, full-PR denial no longer invokes global invalidation. A completed purge permits new authorized reads; it is not a permanent access-denial tombstone. Source reconciliation or a new head/detail read may restore the content that its successful response actually supplies.

## Logical visibility, discovery and restart

Immediately after the barrier, detail/API/list/check readers hide affected payloads even if their physical rows remain. Minimal Activity remains available without excerpts/URLs/actor/head payload fields; local unseen values are unchanged. Watch status reports unavailable and due scheduling excludes pending PR purges, including physically untouched watch rows. Terminal-check classification, selected registration, matching payload/Activity publication and recovery completion honor the marker. Unrelated PR views remain readable.

Deleting a PR from an incomplete discovery traversal cannot silently turn that traversal into a confirmed membership removal. Before removing matching source-stage rows, bounded transactions record `source_restart` guards for each affected source. Other staged rows remain until their normal traversal restart or startup cleanup. A guarded source cannot publish. The worker replaces an obsolete continuation with a fresh first-page plan before issuing another discovery read; first-page initialization atomically clears that source's old stage and restart guard. Unaffected sources may finish independently. Source/list health remains incomplete until reconciliation succeeds. Restart guards contain only source identities and remain until a fresh traversal starts; this is not a new whole-database growth guarantee.

Startup resumes full-PR purge before check purge, Clear, global invalidation and ordinary abandoned-work cleanup. Current-session storage repair does so before retention, committed-write/checkpoint probing and remote eligibility. Clear/invalidation finish earlier PR purges before starting. Full PR purge subsumes overlapping check-purge markers for its locators. Earlier committed batches survive a later error; the failing batch rolls back. Worker storage protection emits the committed revision and stops remote reads while validated cached access remains available. Protected startup remains identity-locked and preserves Pause.

Normal startup still discards abandoned staging/descriptors under its existing bounded policy. Preservation claims for unrelated active staging apply to the PR operation and raw pre-startup inspection, not to intentionally disposable state after normal startup.

## Schema and compatibility

Schema **8** adds the `pr_purge` and `source_restart` tables and the integer `watch_locator.purged_generation` watermark. Older binaries reject the schema rather than ignore unfinished purge/restart barriers. Supported schema 0–7 upgrades remain one fully synchronized atomic migration with space admission before every required step and final commit. Historical schema reconstructions remove the new tables/column as appropriate.

Migration qualification expands to **120 actual SIGKILL cases and 88 injected space failures**, across schemas 0–7 in DELETE/WAL modes. Existing test-only pre-commit dirty-page flushing and real sidecar-byte assertions remain enforced. Actual native schema-8 migration, sufficient peak migration space and signed compatible/incompatible binary replacement remain Pending.

## Remaining gaps and acceptance

The bound applies to each **full-PR purge transaction**, not total synchronous duration, SQLite scanning/sorting/index/page work, temporary allocation, memory or whole-database size. The operation remains serialized until completion or storage protection. There is no VACUUM/file-shrink promise. First-page source initialization/publication retains its separate mutation-bound gap; it runs after a new authorized read, outside PR purge. Generic non-PR `Store::purge` retains its bounded global invalidation plus exact-key path.

LRU admission, source/watch/check publication and recovery-completion mutation bounds remain Pending, as do broader query/cardinality/time/temp qualification and accounting, remaining metadata lifetimes/terminal compaction, physical storage/power loss, sufficient peak migration allocation and missing/legacy/corrupt/unreadable startup recovery UX. Full-size 500-MiB functional capacity/fault tests are rerun against schema 8; no native responsiveness or actual 50-watch capacity is inferred.

Native delivery remains absent. Unattempted-intent reconstruction, reservation/revalidation, pre-dispatch attempts, ambiguous OS delivery and click routing remain unimplemented/unverified. Attempted/unavailable history stays terminal. All **29 grouped release scenarios remain Pending** and existing Blocked live fixtures remain Blocked. No settled contract was reopened or weakened.

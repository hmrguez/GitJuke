# Conversation reader — 2026-10-18

Development 0.1.0; SQLite schema **14**, unchanged. This implements Conversation on the completed Wayfinder decisions and approved Stacks/JetBrains Mono/four-color appearance. Existing uncommitted work is preserved. No planning decision or grouped release gate is changed.

## Reading workflow

The native Conversation tab reads general comments, review submissions (including textless approvals) and review-thread metadata through independent GraphQL cursor connections. Sources retain GitHub node identities, types, nullable authors, source order, timestamps and known totals. Each source keeps its own bounded navigation history. These are independently ordered source pages, not a claim that partial pages form a complete merged chronological timeline. A complete-source label is possible only when the first page contains the entire known source. Subsequent terminal pages still say “this page only.” First/Previous/Next replace pages. Thread metadata starts at 20 records; one selected thread replaces the panel with up to **50 replies**, using its own cursor/history. A First page action remains available after older navigation history is released at 128 metadata entries.

The [GitHub pull request GraphQL reference](https://docs.github.com/en/graphql/reference/pulls) supplies current/original thread coordinates, diff side, outdated/resolved state and root-comment commit identities. Replies fetched through a node ID must also name the requested repository and PR. GraphQL errors, missing nodes, duplicate identities, inconsistent first-page counts and non-advancing cursors reject the entire page. Conversation never publishes Activity source progress or classifies an incomplete traversal as successful hydration.

Body eligibility is inclusive at **131,072 UTF-8 bytes**. Above that, the source identity/metadata remain visible with **Body too large**, no retained/clipped body and a validated source link when available. Missing bodies remain unavailable; an empty supplied review body is a complete metadata-only event. Pages start at 50 messages and halve the requested source window on transport overflow or when serialized page JSON exceeds **921,600 bytes**. This includes escaping; the final Snapshot remains inside the existing **1,048,576-byte IPC ceiling**. A single-source transport or metadata overflow ends with an explicit error; unchanged selected-only failures require explicit retry. No whole-thread prefetch or unbounded append exists.

Only one Conversation component/page is mounted: either the Conversation tab or Changes' inline panel. Source switches, reply navigation and tab changes release inactive bodies. There is no recent-body cache; navigation history contains cursors only. The same retained-body checks enforce **2,097,152 UTF-8 bytes / 100 messages** across both access paths, with the stricter 50-message/900-KiB transfer bounds normally limiting the active set further. Text-segment models retain numeric source ranges rather than a second full array of copied bodies. These are source retention limits, not total allocator/DOM/process-memory measurements.

## Rendering and Changes integration

Bodies deliberately use escaped plain text as the safe fallback. HTML/Markdown remains literal; there is no body HTML insertion, embedded execution, rich-text expansion, image fetching or remote-resource loading. The existing CSP and bundled fonts remain unchanged. Long bodies use explicit Previous/Next segments with source position ranges, each at most 32,768 UTF-16 units without splitting surrogate pairs. Original source identity and GitHub action remain on the message. At most 50 fixed-structure message cards, each with one text node for the active segment, stay below the agreed **5,000 content-node ceiling** by construction. Static React output verifies the structural envelope; instrumented native maximum-page DOM/process qualification remains open. Rich Markdown is not implemented.

Changes exposes the same independently paginated sources and selected-thread panel below its existing reader. A thread attaches only with the exact selected path, valid side, matching recorded commit for that side (head on RIGHT, comparison base on LEFT) and unique known supplied patch coordinates. Multi-line anchors require the same known side and a fully present, unique coordinate range. Previous filenames are not treated as aliases. Outdated threads, missing/ambiguous lines or ranges, mismatched commits, different files and unavailable/limited patches remain labeled in the thread list. Current/original metadata is preserved; old anchors are never remapped onto a current line. This deliberately conservative rule can leave real GitHub LEFT comments unattached when their recorded comment commit names the head rather than the comparison base.

Go to thread selects the separate panel; Return to diff moves to the verified supplied row, using the existing continuous/paged jump and stable outer region focus. No raw-file reconstruction or additional context acquisition exists. Exact GitHub actions are revalidated in Rust against the permitted cached source, the exact PR URL prefix and numeric GitHub comment/review fragment forms. Unvalidated links are omitted. Ordinary source, PR, file, page and thread navigation does not mark Activity seen.

## Invalidation and seen state

Conversation uses the existing serialized worker, durable bounded queue/fairness, server deadlines, 16-MiB transport output cap, SQLite shared disposable admission, retention, storage protection and **128-total-direct-mutation** contract. Unique selected-work tickets, selection epochs, cancellation/reaping, reader-open guards, authenticated stable IDs and global generations reject obsolete results. Head/base/file-count checks surround each full read; the GraphQL PR head must also match. Frontend selection keys, request cleanup and monotonic store-revision floors prevent stale page replacement. Account lock, Clear, full PR purge and resource denial hide/release retained bodies on authoritative reread.

Conversation denial normalizes repository casing and commits a resource visibility/generation barrier before restartable cleanup: at most 32 Conversation content rows plus eight non-check Activity excerpts per cleanup transaction, with accounting/revision included in the 128-mutation guard. Startup and storage repair resume unfinished cleanup. Permitted Overview, Changes, neighbors and durable unseen/dedup/history survive. Activity reads hide discussion excerpts immediately under that barrier. A successful explicit Conversation read restores access; full PR denial keeps the existing full-PR purge policy. No schema migration or general storage redesign is introduced.

Open Activity destination is explicit. Its effect runs after the destination commits to the DOM; segmented bodies require visiting all segments after opening. Only a complete body, including an empty supplied review, can submit a seen receipt. Rust rechecks the selected/open/unlocked PR, generation, permitted cache, complete message and exact body digest before updating the matching namespaced Activity identity. Changed bodies, Clear, denial, eviction and obsolete receipts reject the mutation. Oversized/unavailable placeholders remain unseen. Existing short Activity modal destinations now also revalidate the exact permitted retained excerpt before marking it; Mark loaded page seen remains its separate deliberate snapshot action. Native GitHub navigation does not mark anything seen.

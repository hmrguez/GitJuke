Development 0.1.0; SQLite schema **14**, unchanged. This implements the authorized Changes reading workflow on the settled Wayfinder design. Existing uncommitted storage work is preserved; this is a feature slice, not broader storage or release qualification. No applicable AGENTS.md was found in the workspace or its ancestors.

## Behavior

Changes reuses Stacks, bundled JetBrains Mono and the persisted four-color palette. The navigator replaces **20 file metadata records per page**; one selected unified patch renders at a time. It shows the actual page range, known total and source ceiling. Only a first page containing the entire known list claims complete file-list coverage. GitHub's [files endpoint](https://docs.github.com/en/rest/pulls/pulls#list-pull-requests-files) documents a **3,000-file maximum**. Larger comparisons remain labeled source-limited and link to PR Changes.

Metadata requests use that endpoint; it can supply other files' patches in the response. Those patches are discarded, never prefetched into frontend models or persisted as unselected patches. Only selecting a file requests its patch, through a one-file page at the recorded ordinal. A multi-file transport overflow subdivides the same metadata window into one-file reads, discarding patch text between reads. A one-file overflow is a terminal limited read until an explicit retry; unchanged oversized work does not loop automatically. No full-PR diff request, clone, checkout, raw-file reconstruction or expanded-context downloader exists.

Before and after each comparison read, the worker verifies the head SHA, base SHA and known file count; stable authenticated IDs surround the read too. A selected path must match the file at its ordinal. Cache keys include the comparison identity, page/ordinal, path digest and loading tier. Selection epochs, cancellation tokens, global generations and the selected/open reader guard publication. Unique queue tickets prevent a cancelled worker from acknowledging its replacement. Obsolete jobs perform no GitHub reads; navigation cancels owned selected-only work without interrupting unrelated background jobs. A changed head labels the retained view as old and offers **Update Changes**. A moved base or inconsistent traversal reports an explicit update error instead of publishing a mixed comparison. External gh identity-change races retain the existing documented limits.

Patch eligibility checks both inclusive automatic limits (**524,288 UTF-8 bytes / 5,000 rows**) and explicit-large limits (**2,097,152 bytes / 20,000 rows**), plus **16,384 bytes per logical line**. Rows include hunk headers/context. Structural hunk closure and addition/deletion totals must match before supplied change hunks are called complete. Presence alone does not prove completeness; missing text alone establishes neither binary nor generated status. Explicit binary markers, missing/incomplete text, large opt-in, hard limits, queued/loading, transport errors and access denial remain distinct. Unsupported patches never render a clipped prefix. No generated-file classifier or syntax enhancement is introduced.

Eligible source is stored in content-addressed chunks of at most **98,304 UTF-8 bytes**, then exposed by a final manifest. Each chunk uses the existing shared-budget admission and bounded mutation publisher. A manifest cannot make an evicted chunk complete: transfers validate availability, total bytes/rows and SHA-256 before rendering. The existing serialized **1-MiB IPC ceiling** remains unchanged; JSON escaping is included. Cached matching content stays readable with a latest-fetch error, while clear, access denial and account lock hide it.

Files-access denial commits a Changes-only visibility barrier and generation before bounded disposable cleanup. It preserves permitted Overview, neighboring PRs and durable history. Cleanup takes at most 32 content candidates per transaction, checks the **128-total-mutation allowance** including accounting/revision, resumes after interruption at startup/repair and keeps the barrier until a successful explicit read. Startup examines at most 32 marker candidates per statement. Overview denial retains the existing full-PR purge policy. Clear/purge/retention, the **524,288,000-byte** shared content ceiling, disk protection, queue fairness and server deadlines remain in effect. No schema migration or broad storage redesign is added.

## Reading and accessibility

A visible per-user reading preference persists in Rust-owned settings, defaulting compatibly when older settings omit it. Continuous reading mounts at most **400 patch rows** including overscan. Semantic paged reading replaces at most **200 rows**, with Previous/Next, a row range and a bounded numeric hunk jump. A table exposes old/new line cells and explicit change types. Tabs, spaces, blank lines and change markers remain intact; code scrolls horizontally without wrapping. Hunk navigation explicitly focuses the stable outer diff region. Rows themselves do not own keyboard focus, so virtual eviction cannot remove the focused DOM element.

A Web Worker verifies and parses source away from the UI thread; terminating it and selection tokens reject obsolete parsing. Render-time comparison/path/tier gates also prevent one paint of old rows under a newly selected path. Only the active patch is retained: at most 2 MiB/20,000 rows per model, with worker handoff temporarily duplicating source/model data within the approved **8-MiB/50,000-row source limits**. This is a source-data design bound, not measured total allocator/process memory. File/scroll/page positions use bounded, metadata-only recent maps (128 entries each), scoped to revision/base/file; they survive file/tab navigation in the current frontend session. Reading mode survives full app restart. Navigation never calls Activity seen mutations.

Inline discussions, revision-correct thread attachment and thread jumps are not implemented in this slice. They remain explicitly labeled absent and are the next Conversation slice, sharing its approved discussion bounds. No whole Changes/discussion, accessibility or performance release scenario is promoted.

## Follow-on: Batched progressive loading

The loading pipeline now requests **100 files per batch**, retaining the supplied automatic-tier patches in SQLite before publishing each metadata page. This supersedes the 20-record pages and discarded/unselected-patch behavior above. A 200-file PR needs two Files calls and ten Changes HTTP calls in total: each batch still performs identity → overview → files → overview → identity. Both comparison endpoints, stable authenticated identity, selected-reader/sequence/cancellation and generation guards remain mandatory before any batch content publishes. Metadata cache keys use `files-v2` so old 20-record pages cannot be mistaken for 100-record pages; schema stays unchanged.

Patch cache entries retain the existing revision/path/tier keys, verified digest/chunk protocol, completeness checks, automatic/explicit-large limits and shared content budget. Patches save through batches of at most twelve encoded rows using the existing admission publisher and its 128-total-mutation guard. Chunks precede manifests across commits. Partial writes are disposable; a missing/evicted chunk still fails verification. Transport overflow falls back to one-file reads with a bounded retained payload; patches omitted to fit that fallback remain cold rather than being cached as missing.

All-files mode renders and enables navigation for every completed batch while the next batch loads. Cold metadata and patch work share the native slot; verified cache hits bypass the remote queue, including while another metadata page is pending. Both readers react to cache revisions, with polling retained as a missed-event fallback. Clear/denial/account invalidation stops a progressive traversal and late metadata cannot restore removed sections. Single-file page ranges now use 100-file pages. Models remain viewport-driven and large diffs still require explicit loading.

Regression coverage includes the real Runtime/gh subprocess/SQLite path for 200 files, exactly two 100-file requests with surrounding checks, all 200 cached patch manifests/chunks without a new file download, rejected comparison changes and clear during batch flight, existing cancellation/denial/identity/overflow/large-tier cases, cache-batch rollback/generation/row bounds, and DOM/IPC checks for cached rendering while a later page holds the native slot and late-page rejection after clear.

## Behavior and interfaces

Local queries have a stable, non-reused SQLite ID, UTF-8 bounded name/search and optimistic version. Primary navigation pages configurations at 100 entries; users can create, name, edit and delete them through a native modal and select a query to read its PR results. SQL and gh arguments never interpolate user text into commands. The only remote operation is the existing read-only `Search` through configured gh; `is:pr` is appended. No GitHub saved-view synchronization exists.

`SavedQuery {id,name,search,version}` is durable configuration in `saved_query`. Schema 14→15 adds that table only, through the existing atomic, space-admitted migration runner. Settings/configuration paths, identity, Pause, watch membership, seen/deduplication and history remain owned by their existing stores. Configurations survive restart, shared LRU eviction and Clear downloaded content. Editing a name also increments the version and starts a fresh result cache. Deleting a query removes its durable definition; obsolete disposable page payloads are inaccessible through IPC and remain subject to ordinary shared LRU/30-day retention or explicit Clear.

Typed commands: `saved_queries(offset)`, `save_query(id?,version?,name,search)`, `delete_query(id,version)`, `activate_query(id?,version?)`, `request_query(id,version,page)` and `query_page(id,version,page)`. Updates/deletion require the current version; IDs are not reused. Names/searches accept up to 160/2048 UTF-8 bytes without control characters; these are explicit validation errors, never clipping. Query navigation stays paginated rather than imposing a query-count cap.

Query results use disposable `content` through existing transactional shared admission. Each page has at most 100 results and a conservative 900-KiB stored JSON ceiling, below the 1-MiB IPC ceiling; oversized pages report a narrowing requirement instead of truncating, and a persistent limited flag stops unchanged automatic retries until a manual retry or edit. GitHub's first ten pages/1,000-result limit remains explicit. Every IPC page includes configuration/version, store revision, per-page fetched time, error, provider-reported total, distinct cached count, next page and cached-set completeness. A partial/short/provider-limited response remains visibly incomplete; successful empty results differ from errors and uncached pages. Cached pages from different first-page refresh runs, query versions or global generations cannot be combined. Counts deduplicate stable PR IDs and mismatched per-page totals cannot establish completeness. Search remains mutable between requests; no snapshot-isolation claim is made about the provider.

Only the opened query is automatically eligible, at the existing 60-second discovery target, while its reader is open and monitoring is resumed. Pagination fetches one requested page at a time. Inactive configurations never trigger background Search. Query jobs share the durable serialized/fair queue, existing core/Search budgets, persisted server/backoff deadlines, transport byte/time/cancellation limits, and pre/post stable-ID validation. Explicit reads work while paused without resuming monitoring. Existing global manual refresh includes the active query; the query toolbar can refresh it directly. Automatic first-page refresh replaces the visible run only after success; failures keep valid cached content labeled. Quota denial cannot be bypassed by refresh.

Every commit rechecks query existence/version, cancellation, original identity/session generation and current first-page run for continuations. A queued obsolete version is acknowledged without a read; a result arriving after edit/deletion is never published, even to an invisible old-version cache. Global lock/clear/denial generation barriers reject late results. Query-specific denied responses commit a durable per-query run barrier and hide only that query’s results; configuration and unrelated cached resources survive. Full-PR denial’s existing global generation barrier conservatively hides earlier query pages so denied PR metadata cannot remain exposed in an old search page. Query list items never enroll watches; only opening a PR follows the existing selected-PR reader/watch contract.

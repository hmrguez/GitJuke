## Implementation and interfaces

Checks offers **Read Actions log** only for a supplied Actions job URL matching the repository and workflow run. Other checks expose **Open provider details**. Opening a link re-reads the permitted check context and accepts a bounded absolute HTTPS URL without credentials, controls, whitespace, backslashes or a custom/executable scheme. No browser loads or provider requests happen merely by rendering a link.

`request_logs(LogJob) -> ticket`, `read_logs(ticket) -> {state,text}`, `cancel_logs(ticket)` and `open_check_details(LogJob)` are the new Tauri commands. `LogJob` contains repository, PR number, current head, check node ID and current check-page offset; the backend assigns its own monotonic ticket. Callers must release their ticket on navigation; cancellation of an old ticket cannot release its replacement. Request descriptors and terminal results are **memory only**. They are never enqueued in SQLite and cannot replay at startup. They share the existing 128-descriptor fair serialized queue, explicit-Pause permission and core/server backoff policy. There is no automatic log retry.

The backend retains one replaceable log slot. It validates the permitted current check context, complete commit snapshot, selected PR, reader-open state, account generation and resource epoch on publication and every read. Remote reads verify the PR head, workflow run/attempt/head, job/run/attempt/commit/URL and the exact GitHub Actions check node association before and after the log response, with stable-account probes around the operation. A changed head, attempt, selected check, check snapshot, resource epoch or account discards the result. Detected PR denial invokes the existing resource purge; log-only denial does not erase otherwise accessible PR content or durable Activity history. These checks reduce mutable external-account races; they cannot establish an absolute race-free remote snapshot.

The installed `gh api` reads the single job's [documented raw log endpoint](https://docs.github.com/en/rest/actions/workflow-jobs#download-job-logs-for-a-workflow-run); it does **not** use `gh run view --log`, ZIP extraction, signed-URL files or a disk-backed log cache. Fixed typed operations construct API paths. The existing one-child gate, 30-second child deadline, 16-MiB stdout / 64-KiB stderr ceiling, cancellation and process-group terminate/grace/kill/reap remain in force. API accounting persists counts/deadlines only, never log bodies, provider diagnostics or signed redirect URLs. Production has no fixture fallback.

The local inclusive log source limit is **131,072 UTF-8 bytes**. Responses over it become `oversized` without returning a clipped prefix; transport overflow is also oversized. Complete worst-case JSON escaping fits the existing **1-MiB IPC** ceiling. Invalid UTF-8, unsupported redirect/header behavior and failed subprocess responses fail explicitly. The frontend keeps the current source in memory, renders plain text in pages of at most **200 logical lines**, and offers no HTML, Markdown, image or remote resource execution. Log text keeps horizontal scrolling and a 24-rem maximum local height. These are source/render bounds, not a measured process-RSS guarantee.

States are `queued`, `reading`, `complete`, `empty`, `denied`, `expired`, `missing`, `oversized`, `failed`, `released`. HTTP 403 without quota signals is denied; HTTP 410 is expired; HTTP 404 is missing/unavailable and does not claim deletion or prove whether permission/retention masked it. A successful zero-byte response alone is empty. Quota/server/network/schema failures remain failed or queued at a known deadline. HTTP 401 follows the global identity lock and release path. Provider diagnostics are never displayed as a log or persisted as resource errors.

Leaving the log/tab/PR, selecting another log, closing the reader, Clear downloaded content, configuration/account changes, invalidation and storage protection release backend ownership and cancel obsolete work. React unmount/visibility/reader-close handling drops source references and ignores late IPC; periodic and revision-driven reads recover missed invalidation events. Rust allocation release and JavaScript garbage collection do not promise physical zeroization or an immediate OS RSS decrease.

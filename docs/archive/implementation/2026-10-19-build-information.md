# Binary-owned build information — 2026-10-19

GitJuke now identifies the running binary in **Preferences → About** and **startup recovery → About this build**. This completes the local version/build presentation portion of the confirmed manual-update contract in [Choose macOS packaging, signing, and distribution](../../../.scratch/gitjuke/issues/10-packaging-signing-distribution.md). All **29 grouped acceptance scenarios remain Pending**.

## Selection and implementation

Inspection started from `e10c4101a5c1258f58a398a2f9a329c602c11d66`, with existing edits to map/spec/acceptance/status preserved. The current code already contains the merged chronological Conversation timeline. The signed/notarized v0.1.0 early release exists; historical statements that signing or chronology are still unimplemented are stale. External-suite alerts still require authoritative attempt identity, and the historical palette-contract conflict was left untouched. Broader live providers, signed notification opt-ins, real login and reference hardware require prerequisites outside this local implementation slice. Binary identification was a concrete remaining contract gap that could be completed without those prerequisites or changing settled behavior.

`src-tauri/build.rs` embeds the package version, a build ID, Git HEAD and source state, Rust target/profile and the binary's data-format version. The new `build_info` Tauri command needs no Runtime, SQLite connection, gh executable or authenticated identity. It reads neither Git nor environment variables when the app runs. It exposes no source paths, account data, signing credentials or inherited environment contents.

Local build IDs use `local-<compilation Unix seconds>`; official workflow builds receive `ci.<run number>.<attempt>`. An explicit `GITJUKE_BUILD_ID` must contain 1–64 ASCII letters/digits/dots/underscores/hyphens or compilation fails. Source archives and source directories inside an unrelated parent repository report unavailable, rather than adopting a misleading parent revision. Modified worktrees are labeled explicitly. Cargo watches frontend/backend/build inputs and Git pointers, so frontend-only changes also refresh the embedded stamp. An unchanged compiled binary keeps its stamp.

These fields identify a compilation; they are **not** an artifact checksum, a fingerprint of every modified byte, proof of a clean checkout, signature verification, a CI provenance attestation or compatibility certification. `release` is the Rust profile, not a signing claim. The displayed data format is the binary's schema constant (currently **16**), not a query of a failed/newer database. No schema migration or compatibility policy changed.

The small About view follows the existing typography/palette/dialog styles, shows selectable source text, and explains explicit Quit/replacement/relaunch. Startup recovery can display the same information while private readers remain unmounted. A failed metadata IPC read has an independent retry. No update checker, download/install action or new frontend fallback was added. The release workflow change only supplies future build metadata; it was not dispatched.

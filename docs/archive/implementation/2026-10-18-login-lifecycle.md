## Behavior and shared interfaces

The official Tauri autostart plugin is configured explicitly with `MacosLauncher::LaunchAgent`, a label equal to the configured bundle identifier, and exactly `--background`. Its generated LaunchAgent uses `RunAtLoad`, with no KeepAlive/watchdog, periodic launch or crash restart. Only the guarded Rust commands are exposed; autostart plugin IPC permissions were not granted to the frontend. Default is off. A small, separately durable `login.json` stores user intent in the identity-specific app-data directory; it does not change SQLite schema, account binding, Pause, themes or alert settings. Writes use a synchronized temporary file, atomic rename and directory synchronization. Invalid existing preferences are preserved and reported.

`login_status` is read-only. `set_launch_at_login {enabled,repair}` is the only registration mutation path. Startup never enables, recreates or repairs registration. A background invocation with a saved off preference exits before runtime initialization, so a leftover file cannot defeat a partial disable. Explicit enable/repair validates the current executable and canonical bundle path plus CFBundleIdentifier, registers through Tauri, and explicitly clears a launchd disabled override. Disable persists off, disables the label and removes its file without booting out/killing the running monitor. Partial errors retain user intent and expose actual registration for explicit repair. Inspection distinguishes preference, plist existence, exact executable/arguments/label, installation validity, unknown status and launchd OS-disabled overrides. Both boolean and enabled/disabled `launchctl print-disabled` formats are recognized. A plist alone is never proof of successful login execution; Background Task Management/Login Items may still deny execution.

Production monitoring and registration require `/Applications/GitJuke.app/Contents/MacOS/gitjuke`, canonical without symlink relocation, and the matching bundle identity. Moved/download/DMG/translocated bundled copies show install guidance and do not initialize a runtime/store writer. A periodic installed-path check also shuts down a running scheduler if its bundle is moved or removed; restoring the file does not restart that worker automatically. Registration is not silently migrated or removed when paths disappear. Explicit disable remains available. Bare debug `tauri dev` and explicitly separate debug reader/log/accessibility qualification identifiers remain available for their isolated monitor namespaces; those other identifiers cannot register login. Normal-identity bundled debug copies still require the installed path. A moved lifecycle-qualification copy follows the same refusal policy being tested. A debug-only `lifecycle-qualification` feature permits one fixed separate identity and `/private/tmp/GitJuke Lifecycle.app` for native qualification. Release builds have no alternate path or fixture fallback.

A kernel `flock` is acquired in an OS-account + application-identifier namespace before the runtime opens SQLite. It is independent of HOME or per-launch configuration directories, so Finder/login/shell contexts cannot create different owners. Socket binding occurs synchronously under that lock. Contenders forward only a bounded manual/background discriminator and exit; failures time out closed without opening a second runtime. The socket lives in a short, account-owned 0700 temporary directory keyed by that stable ownership namespace, avoiding the macOS socket-length limit for long user/configuration paths. Socket cleanup occurs only under ownership; the lock inode is never unlinked. The kernel releases ownership after a crash. OS-level socket bind/ownership errors fail closed into a stopped guidance shell; they never open another store writer. The previous plugin's asynchronous socket bind could continue after a race/failure; it is replaced by this atomic ownership boundary.

The reader starts hidden in Tauri configuration. `Runtime::start_background` initializes reader-open/visible false before spawning scheduling, preserving selected-only close semantics and stored Pause. Normal launch, tray Open and Reopen share `show`; closing hides and drops selected-only membership. Background duplicate launches never activate the reader. The menu bar exposes setup/auth/Paused health with user-invoked Open guidance. Runtime initialization and ownership failures retain a stopped guidance shell rather than initialize another store writer or replace data. Quit is idempotent, suppresses later activation, synchronously calls `Runtime::request_shutdown`, blocks new login-control work, awaits the existing Runtime shutdown/cancel/reap path, drains any bounded local launchctl operation so its child is reaped, and exits while preserving next-login intent. Ordinary reads and the existing alert identity/head probes use `Runtime::work_token`, a child of the stop token, so cancellation propagates before the async reap is polled. Eligibility checks stop before materializing another work item. There is no watchdog or relaunch command.

The combined build retains the existing native alert interface: `NotificationRoute(Mutex<Option<i64>>)` → `take_notification_route` → `Runtime::notification_destination` → existing exact Activity/Conversation destination handling. The existing native delegate poll stores an opaque intent ID and calls the same guarded `show`; background startup only initializes the delegate and never invokes `NativeAlerts::request`. No CLI deep-link parser, second destination resolver or seen mutation is introduced by login lifecycle. The adapter initializer, runtime sink, notification commands and exact-route frontend are retained. Both native poll loops stop at Quit, and the notification poll also stops after path invalidation. Alert permission, dispatch/attempt and privacy remain owned by the [native-alert slice](2026-10-18-native-alerts.md). The only notification-control copy change removes its obsolete assertion that login is never enabled.

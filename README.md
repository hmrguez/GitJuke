# GitJuke

A read-only macOS GitHub PR reader and personal activity monitor built with Tauri, React, Rust, SQLite and the installed `gh` CLI.

Production implementation started on 2026-10-17 under the settled specification. The runtime reads the existing stored gh identity, reconciles open authored/direct/team/selected watches, schedules batched head/check snapshots, reads PR overviews/published native stacks and selected Changes patches, discovers notification threads and hydrates individual personal Activity with durable baseline/recovery and seen/dedup state. The production app has no fixture fallback. This is an incomplete development build, not a release-ready monitor: saved queries, native alerts, logs, login lifecycle, startup recovery and reader accessibility are integrated; daily-use and release qualification are tracked separately.

Changes defaults to an All files view: it loads 100-file batches, caches supplied patches, and displays each batch immediately while later files load. Revision-bound diffs load from cache near the viewport; switching cached files requires no GitHub request. The navigator jumps directly to each file, and Single file retains the focused reader. Automatic/explicit-large limits, verified chunked IPC, continuous virtualization and semantic paged reading remain available. Missing/incomplete/binary/limited/denied content stays labeled; source links fall back honestly to PR Changes. Reading mode persists; file/scroll positions are remembered within the current frontend session. Native automatic-tier reading was exercised on a public PR. Conversation now adds independent comment/review/thread pages and bounded selected replies, shared safe plain-text/segment rendering, conservative revision-correct inline anchors and explicit seen receipts. Positive owned-repository live/native thread evidence is now available; full native accessibility/performance qualification remains open. See the [Changes implementation and evidence](docs/implementation/2026-10-18-changes.md); no grouped release scenario is promoted.

Activity comment/review destinations now resolve their exact retained GitHub node directly in Conversation, including bodies beyond the 8-KiB Activity excerpt through the existing inclusive 128-KiB reader path. Only the explicitly opened matching complete body can submit a seen receipt; segmented bodies require every segment, and ordinary source navigation leaves Activity unseen. Back to Activity restores the list/focus; exact supplied reply coordinates can attach within the matching Changes patch, with outdated/unavailable anchors labeled. See the [destination checkpoint and evidence](docs/implementation/2026-10-18-destinations.md) for deterministic, positive live and native scope. All 29 grouped release scenarios remain Pending.


Historical reader-navigation checkpoint: keyboard reading gives scrollable message bodies their own focus target, restores originating thread/Activity focus, and keeps focus stable across source, segment, file and semantic-row page replacement. Native default/compact observations include keyboard message scrolling, source/thread return and a second live file page; live unseen/segmented fixtures, VoiceOver, actual 200% text zoom and reduced-motion qualification remain open. See the [reader navigation checkpoint](docs/implementation/2026-10-18-reader-navigation.md).

Leaving the view, invalidation, account/configuration changes and reader close release the log; stale head/run/attempt/resource results cannot publish. No log body enters SQLite or an application file. See the [log reader checkpoint](docs/implementation/2026-10-18-logs.md) for scoped verification, evidence distinctions and integration limits.

Native macOS Activity alerts now have skippable explicit opt-in, category controls, generic previews and optional cached metadata previews. ## Develop

Apple Silicon, macOS 15+, Rust, Xcode command-line tools, Bun 1.4.2+ and an existing stored GitHub.com `gh` login are required. GitJuke neither installs gh nor changes its credentials. The default config directory is the OS account's `~/.config/gh`, independently of shell token/XDG overrides. Preferences accepts explicit absolute executable/configuration paths and revalidates the originally bound stable account.

```sh
bun install --frozen-lockfile
bun run tauri dev
```

`bun run dev` alone opens a browser frontend without a native runtime; it reports that limitation and supplies no sample PRs. The native app stores its database in the Tauri application-data directory for `dev.hmrguez.gitjuke`. Close hides the reader; Cmd-Q or tray Quit cancels/reaps remote work and exits. Pause and four-color appearance settings persist. Startup transient cleanup and recovery initialization each commit at most 128 direct row mutations per cleanup transaction and resume safely after interruption before monitoring starts. Recovery commits its boundary before batched resets, preserving it through partial failure. Watch-derived Activity enrollment adds at most 128 missing targets per scheduling pass; recovery cannot complete while eligible watches await enrollment. Full-PR denial unifies overview/Activity/watch purging behind a durable generation/visibility barrier and cleanup transactions of at most 128 mutations; affected discovery restarts before publishing, while durable history and unrelated caches survive. Check-access denial commits a per-PR epoch barrier, hides denied contexts and check Activity excerpts, and resumes cleanup in transactions of at most 128 direct mutations during startup/repair. Unrelated PR content and durable history survive. Clear downloaded content commits a logical/generation barrier, hides pending payloads and resumes cleanup in transactions of at most 128 direct mutations during startup/repair, preserving durable history and deadlines. Global invalidation commits a generation barrier before restartable 128-row cleanup; pending invalidation makes cached checks incomplete and resumes during startup/repair. Existing current-schema databases can start in storage protection; validated sessions retain cached navigation when writes fail. First-page PR discovery initialization commits a source restart guard before deleting old staging in transactions of at most 128 direct mutations; unfinished initialization blocks staging/publication and recovery completion while cached membership remains readable. Source/watch/check publication now uses complete transactions capped at 128 direct mutations including admission; small operations commit once, while larger replacements use a durable old-snapshot journal, bounded application and one visibility commit. Startup/repair finish interrupted publication before eligibility; exact retries preserve membership and epochs. Activity staging initialization also uses bounded cleanup and staging commits; Activity publication and recovery completion share the 128-mutation maximum, retaining one transaction for small sets and journaled atomic visibility for larger histories/summaries. Protected Activity/seen/dedup/progress/cycle/intent/member reads prevent premature completion; startup/repair finish interrupted publication before abandonment cleanup or remote eligibility. All eight payload writers use shared transactional admission, reserving publication writes and revision from the same 128 allowance. Admission adds at most 128 mutations per candidate; larger reclamation first rolls back publication, then commits independent LRU batches capped at 128 total mutations including check invalidation and revision, before retrying atomic publication. Staging and durable history remain protected; earlier disposable reclamation may survive a later publication failure. Historical full-size fixtures retain their recorded applicability. The current schema-16 daily qualification reruns all ten actual-ceiling/full-ceiling cases and the supported-version migration matrix; worst-case cumulative query, complete temp/peak-space and reference performance bounds remain unqualified. Check snapshots enforce 30-day access expiry and report incomplete state after eviction. Periodic retention also runs while paused. One global allowance caps each retention transaction at 128 direct mutations, including dependent Activity/payload/catch-up deletion, check invalidation, validator/API-health/obsolete-check reclamation and revision. Logical expiration applies while physical cleanup waits; expired loaded snapshots cannot mark Activity seen. Head-reservation retry cleanup, abandoned Activity retry staging and manual watch-due resets now use durable scoped sweeps capped at 128 mutations including final bookkeeping; startup/repair finish them before scheduling, preserving cached payloads, deadlines and durable history. Retention selection now uses indexed ranges and fenced 128-candidate keyset windows with atomic cursor/deletion commits; zero-sort/automatic-index plans are qualified against large protected prefixes. Publication application uses a partial unapplied-row index. Shared admission now reads transactionally maintained byte totals and selects the exact shared LRU prefix through indexed check-snapshot frontiers and bounded successor seeks, avoiding repeated full payload/journal/context traversals. Trigger bookkeeping shares every covered 128-mutation allowance; schema-13 startup/repair preserve old-snapshot publication visibility and durable history. Compact oracle, fault, retry and process-kill evidence covers these changes; cumulative duration, publication planning, deep reader/queue queries, variable bytes and total temp space remain unqualified. Preferences reports database/sidecar sizes separately from disposable content, with a 1-GiB measured-file warning; transient sort-file accounting remains pending. Activity denial purges use literal PR path boundaries so neighboring PRs retain their caches. Startup never requests notification permission or creates login registration; their separate explicit controls own those opt-ins.

```sh
bun run build
bun test                  # JavaScript diff tests
bun run test:rust         # Rust core tests
bun run test:all          # Both suites
cargo test --workspace --offline
bun run check
bun run tauri build --debug --bundles app --target aarch64-apple-darwin --no-sign
```

`bun test` runs the JavaScript suite; `bun run test:rust` runs Cargo. `bun run test:all` runs both. The existing `test` script remains a Rust-only alias for compatibility. Node/npm are only needed to reproduce the legacy JavaScript benchmark. Dependencies are pinned in `bun.lock`; Bun also runs the JavaScript build tools. See the [Bun migration benchmark](docs/implementation/2026-10-18-bun.md) for timings and reproduction.

The last command produces a **local development app**, not the signed/notarized/stapled release DMG. No signing credentials, membership, publication or distribution have been provisioned. Development version 0.1.0 now reads schema **16** and transactionally upgrades fresh schema 0 and schemas **1–15** (including either independent schema-15 feature layout), with full SQLite synchronization before migration writes and free-space checks before every upgrade step and commit; unknown future or corrupt schemas stop with original files preserved. There is no updater or automatic destructive reset.

Publication preparation now commits at most twelve native candidates with a durable cursor/fence before filtering and indexed point joins. Recovery readiness uses 128-row windows in one snapshot; published check completion reads an exact maintained count. Added cursor and trigger bookkeeping remains inside the 128-mutation cap. Atomic visibility and durable history remain protected. Cumulative traversal time, variable-byte/temp bounds and native performance remain unqualified.

All windows and pending/source checks share one read snapshot; pending publication blocks native scans. Selection adds zero mutations or persistent state, and schema remains 14. Total traversal time and broader reader/queue/sweep/variable-byte/temp/native gates remain open.

A 128-rank heap preserves foreground priority and the exact oldest-background reservation; final descriptors return in sequence order. Policy and body reads share one snapshot, pending publication blocks native scans, and selection adds zero mutations or persistent state. Schema stays 14. Cumulative traversal time, other watch/queue scheduling, reader/sweep queries and variable-byte/temp/native gates remain open.

Watch scheduling now uses indexed 128-candidate watch/pending windows and streamed one-entry head-reservation checks against at most 128 candidate flags. The exact selected-PR/due/ID order, caller limit, disjoint batches and manual boundary are preserved in one snapshot. Selection adds zero writes or persistent state; schema remains 14. Repeated traversal, whole-job/path/entry parsing, variable bytes/temp space and native performance remain open.

Watch-list pages now use 128-candidate native/journal windows and bounded old-key merging, preserving stable-ID order, 100-item pagination, complete ordered reasons and the existing 900-KiB item budget. Rows, reasons, denial labels and revision share one snapshot; cached pages retain old/new publication visibility. Reading adds zero writes or persistent state, and schema stays 14.
